Movie Performance Analytics Engineering Pipeline

Movie Performance is an end-to-end analytics engineering project that turns public movie rating, genre, budget, and revenue datasets into business-ready entertainment reporting. Raw CSV files are staged in Amazon S3, loaded into Snowflake, transformed with dbt into analytical models, enriched with Python-supported genre logic, and visualized in Power BI for revenue, rating, genre, budget, and ROI analysis.

Solution Architecture

The pipeline follows a source-to-dashboard analytics workflow. Public movie CSV files are downloaded from Kaggle-style datasets and staged in Amazon S3. Snowflake loads those files into a raw schema through a configured external stage, preserving the source data before transformations are applied. dbt then builds source, dimension, fact, and mart models in Snowflake. Python supports genre normalization logic, and Power BI connects to the curated Snowflake models for business-facing reporting.

  • Amazon S3 stores the raw movie CSV files before warehouse loading.
  • Snowflake separates raw landing tables from dbt-built analytical models in the `MOVIELENS` database.
  • dbt standardizes source data and creates analytics-ready dimension, fact, and mart models.
  • Python supports consistent genre ordering and enrichment logic for downstream analysis.
  • Power BI consumes the curated Snowflake models for interactive revenue, rating, genre, budget, and ROI reporting.

Transformation Layer

dbt transforms the raw Snowflake tables into analytics-ready models. The transformation layer is organized into source/staging, dimension, fact, and mart folders so raw standardization, analytical entities, measurable events, and final reporting outputs remain separated.

  • Source and staging models standardize raw MovieLens-style files, rename fields, convert timestamps, and prepare clean model references.
  • Dimension models define analytical entities such as movies, users, movie tags, and genome tags.
  • Fact models organize ratings, genome relevance scores, revenue, budget, release, and ROI-oriented data.
  • The mart layer creates reporting-ready outputs for Power BI, including release metadata availability logic.
  • dbt documentation, tests, and lineage make the transformation workflow easier to inspect, validate, and maintain.

The fct_ratings model is configured as an incremental dbt model. During future runs, it can process only newly added rating records instead of rebuilding the full ratings table, which supports a more scalable refresh pattern for large rating datasets.

Python Enrichment

Python supports the enrichment layer by preparing genre logic for consistent analysis. The workflow uses pandas and a manually defined genre hierarchy to normalize raw genre strings and support cleaner genre ordering across reporting outputs.

  • Organizes raw genre values into a more consistent analytical structure.
  • Supports genre comparison across revenue, budget, rating, and ROI metrics.
  • Improves dashboard readability by applying consistent genre ordering and category logic.

Dashboard and Reporting Layer

The Power BI reporting layer connects to curated Snowflake models and presents movie performance through executive-style KPIs and supporting visuals. The dashboard is designed to help users compare revenue growth, genre contribution, movie-level profitability, and performance against a baseline.

  • KPI cards summarize movie count, average rating, average revenue, average budget, and average ROI.
  • Revenue by decade compares projected revenue against actual revenue trends.
  • Genre visuals show revenue contribution and profit performance against a baseline.
  • Movie-level detail tables support title, genre, rating, revenue, budget, and ROI review.
  • Interactive filters allow users to slice the report by decade, genre, rating range, and movie title.
