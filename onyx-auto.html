Onyx Auto: End-to-End Data & Analytics Engineering Platform

Onyx Auto is an end-to-end analytics engineering project that simulates a used car dealership data platform. The system captures operational dealership data in a PHP and MySQL application, ingests it into Snowflake with Airbyte, transforms it through dbt staging, intermediate, and mart layers, orchestrates the workflow with Airflow, and delivers executive reporting in Power BI.

Business Problem

Turning dealership operations into reliable reporting.

Used car dealerships need visibility into inventory, sales, parts activity, seller quality, and operational performance. Raw transactional systems are useful for recording day-to-day activity, but they are not always designed for analytical reporting. This project models how a dealership can move from operational data capture to structured reporting.

Sales visibility
How much net income and gross sales income has the dealership generated?
Inventory health
How long are vehicles remaining unsold?
Sales performance
Which sales agents are driving monthly performance?
Seller risk
Which sellers are associated with higher parts costs?

Architecture Overview

Source-to-dashboard analytics workflow.

The architecture begins with operational dealership data captured in a PHP frontend and stored in MySQL. Airbyte syncs MySQL source tables into Snowflake, where the raw data lands in a dedicated raw schema. dbt transforms the raw data into staging, intermediate, and mart models. Power BI connects to the final mart models, and Airflow coordinates the refresh process with Teams-based failure alerts.

Source Application and Database Design

Operational system modeled before analytics begins.

The source system is a PHP dealership application backed by a MySQL transactional database. It captures customers, vehicles, vendors, parts orders, users, employee roles, and sales transactions. Vehicles are keyed by VIN, and sales are stored in a separate table so unsold vehicles can remain in inventory without requiring null sale-related fields.

Airbyte Ingestion Layer

Incremental MySQL-to-Snowflake synchronization.

Airbyte moves operational data from MySQL into Snowflake. The connection syncs dealership streams such as customers, vehicles, sales, parts orders, vendors, manufacturers, users, and employee role tables. The destination lands raw source data in DEALERSHIP_RAW.MYSQL_LOAD. The connection uses an incremental append-and-deduplicate pattern with an updated_at cursor field.

dbt Transformation Layer

Layered transformation from raw tables to reporting marts.

The dbt project, dealership_data, transforms Airbyte-loaded MySQL data in Snowflake into analytics-ready dealership models. The project uses a medallion-style structure with staging, intermediate, and mart layers. Staging and intermediate models are materialized as views, while mart models are materialized as tables for stable Power BI consumption.

Staging
Standardizes raw source tables and prepares clean references for downstream logic.
Intermediate
Applies reusable business logic for customers, employee roles, vehicle status, financials, parts costs, and sales enrichment.
Marts
Creates reporting-ready dimensions, facts, and aggregates for Power BI dashboards.
Testing & documentation
Documents models and validates uniqueness, non-null fields, and relationships.

Power BI Reporting Layer

Business-facing dashboards built from curated marts.

Power BI is the final consumption layer for the platform. The report connects to curated Snowflake mart models built by dbt and presents dealership performance through executive, sales, inventory, parts, and seller-risk report pages.

Airflow Orchestration and Monitoring

Scheduled workflow from ingestion to semantic model refresh.

Apache Airflow orchestrates the daily Onyx Auto pipeline. The DAG is named onyx_auto_pipeline and is scheduled to run at 3:00 AM. The workflow triggers the Airbyte sync, waits for ingestion to complete, runs the dbt build, refreshes the Power BI semantic model, and sends Microsoft Teams alerts if a pipeline task fails.

Key Outcomes

What this project demonstrates.

Onyx Auto demonstrates the full analytics engineering lifecycle: source-system design, ingestion, cloud warehousing, layered dbt transformation, dimensional modeling, dashboard development, orchestration, and monitoring. The project shows how raw operational data can be captured, modeled, governed, refreshed, and delivered for business reporting.

  • Built an end-to-end analytics workflow from PHP/MySQL source data to Power BI reporting.
  • Designed Snowflake raw and analytics schemas to separate source data from curated reporting models.
  • Implemented dbt staging, intermediate, and mart layers with facts, dimensions, and aggregates.
  • Created executive and operational Power BI reports for sales, inventory, parts, and seller-risk analysis.
  • Orchestrated the refresh workflow with Airflow and simulated operational monitoring through Teams alerts.

The main lesson from the project is that each layer of the analytics system should have a clear responsibility: the source application captures data, Airbyte ingests it, Snowflake stores it, dbt transforms it, Airflow coordinates it, and Power BI communicates the final data product to business users.
